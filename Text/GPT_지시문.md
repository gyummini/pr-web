# 화면 문구 검수 지시문 (Codex용)

이 저장소(PR_web)는 게임 기획 직무 지원자 김경민의 포트폴리오 웹사이트다.
사이트에 나오는 문구를 검수해 최종 문구로 확정하는 것이 이번 일이다.
최종 문구는 GPT(지금 이 작업)가 쓴다. Claude는 목록과 도구만 준비했다.

## 2. 사이트와 독자

- 컨셉: 방문자가 탐정이 되어 지원자의 '사건 파일'을 뒤진다. 조수 캐릭터 '클루'가 안내한다.
- 독자: 게임 회사의 채용 담당자와 현업 기획자. 짧은 시간에 지원자를 판단한다.
- 흐름: 인트로 대화 → 기본 사항(이력서) → 세부 사항(자기소개서 CASE 01~04 · EPILOGUE, 문장 속 형광펜이 증거로 이어짐)
  → 증거 보관함(포트폴리오 문서와 인터랙티브 페이지) → 히든(클루의 수사 수첩).
- 문체 참고
  - 10/01 교정 방향(사용자가 승인한 것): 내부 용어와 축약을 걷어내고, 처음 보는 사람이 바로 읽히는 문장으로.
    분석 용어는 일반어로, 메모체는 완결 문장으로, 버튼은 누르면 무엇이 나오는지로. 자세한 예는 `작업진행.md` 5장 '10/01' 항목.
  - 클루의 말(인트로·엔딩 대화, 팝업 대사, 수첩)은 `캐릭터_조수_클루.md`의 톤 가이드를 따른다.
  - 같은 화면의 확정 문구와 톤을 맞춘다. 요청문(아래 3-3)에 '같은 화면의 다른 문구'로 함께 나온다.
- **E8 페이지 구성(10/07)** — 문구가 놓이는 자리를 알고 쓴다.
  - 첫 화면: 머리말(제목 · 부제) → 큰 제목 · 도입 문단 → **여덟 장 지도**(가운데 실제 게임 팩 그림, 그 아래 기준 한 줄,
    양쪽에서 네 장씩 '번호 · 한 단어 · 장 제목'이 선으로 모여 팩을 가리킨다) → '한눈에 보기' 상자 → 숫자 표 · 기간과 도구.
    오른쪽에는 타이틀 화면과 '직접 플레이하기' 버튼이 따라 내려온다.
  - 장(01~08)마다: 왼쪽에 장 이름 · 장 제목 → 결정(굵은 문단) → '제가 한 일' 상자 → 본문,
    오른쪽에 증거 패널(작은 그림 탭으로 고르는 그림 · '참고 | 결과' 짝, 바닥에 'AI가 한 일' 한 줄). 그림은 본문 사이가 아니라 이 패널에 있다.
  - 끝: 직접 플레이 버튼, 늘 펼쳐 둔 '비공식 프로젝트 및 IP 안내', 접혀 있는 '저작권과 출처'.
  - 좁은 화면(1180px 이하)은 한 단이다. 증거 패널은 그 장의 '제가 한 일' 다음, 본문 앞에 온다.

## 3. 진행 방법 — 화면 하나씩

1. **처음 한 번**: `cd tests && npm run setup` (테스트용 브라우저 설치).
2. **화면 고르기**: `E8`(180) 먼저 → 나머지(`node tools/strings.cjs request`를 인자 없이 돌리면 남은 전부 — E3 · E5 · E2 새 자리).
3. **요청문 뽑기**: 저장소 루트에서 `node tools/strings.cjs request E8`
   → `Text/GPT_요청문.md`. 'E8'이 든 화면(E8 인터랙티브 페이지 · E8 요약 메모(팝업) · E8 증거 카드)의 DRAFT 문구마다 지금 문구와 맥락(context)이 나온다.
   장 안의 문구는 장마다 화면 순서대로 나온다. 여러 문구에 같은 맥락은 맨 위에 한 번만 적힌다('따로 적지 않으면 공통').
   인자는 화면 이름의 일부다(`E8`, `E3`, `수첩`, `기본 사항`, `알림` …).
4. **화면에서 보기**: `cd tests && npm run serve` → `http://127.0.0.1:4173` + 아래 경로.
   - `/` 인트로 · `/basic` 기본 사항 · `/case/01`~`/case/04`, `/case/epilogue` 세부 사항 · `/evidence` 증거 보관함
   - `/evidence/E1`~`E8` 증거 상세 · `/evidence/E1|E2|E3|E5|E8/interactive` 인터랙티브 페이지 · `/docs` 문서만 모아보기
   - 수첩(`/notebook`)과 엔딩(`/ending`)은 증거를 다 모아야 열린다. 내용은 데이터 파일로 보면 된다.
   - 문구가 화면 어디에 어떻게 그려지는지는 `assets/js/views/*.js`, `assets/js/briefs/*.js`(E1 `character-call` · E2 `flow` · E3 `cut-play` · E5 `one-card` · E8 `retro`)에 있다.
   - E8의 '직접 플레이하기'는 누르지 않는다 — 누르면 개인 키가 실제로 발급된다.
5. **답 쓰기**: `Text/답/E8_1007.txt`처럼 화면마다 파일 하나(지난 답 파일은 그대로 둔다). 한 줄에 하나씩 `키 = 문구`.
   그 화면의 **모든 DRAFT 키에 답**한다(그대로 둘 문구도 그대로 적는다). 문구 앞뒤 공백 말고는 적은 그대로 들어간다.
6. **넣기**: `node tools/strings.cjs apply Text/답/E8_1007.txt`
   → 데이터 파일에 그대로 반영되고 그 행이 `FINAL`로 바뀐다. 자리표시가 다르거나 `[임시]`가 남아 있으면 아무것도 넣지 않고 거부한다.
7. **확인**: `node tools/strings.cjs check` 와 `cd tests && npm test`(여섯 묶음 모두 통과해야 한다).
   화면에서 버튼·라벨이 넘치거나 어색하게 줄바꿈되지 않는지 본다(좁은 화면 390px도). E8은 첫 화면 지도의 장 이름 · 장 제목과 PC 옆 목차를 꼭 본다.
8. **기본 사항·자기소개서·PDF 문구를 바꿨다면** `cd tests && npm run pdf`로 `이력서.pdf`, `이력서_자기소개서.pdf`를 다시 만든다.
9. 다음 화면으로.

## 4. 바꾸면 안 되는 것

- **사실.** 숫자, 기간, 사람·캐릭터·게임·세트·이벤트 이름, 게임 규칙과 수치. 원본 문서·이력서·자기소개서에 없는 사실을 더하지 않는다.
  E5의 원본은 <https://arcana-test-nine.vercel.app/>(인터랙티브 기획서)다.
  E8의 표지 숫자(2주 · 199개 · 약 3.9만 줄 · 4,536장 · 약 900개 · 24.5MB), 키 수 · 기간(50개 · 60일 · 10분)도 사실이다.
- **권리 표기(E8 '저작권과 출처' · '비공식 프로젝트 및 IP 안내').** 회사 · 작품 · 사람 이름, 연도, ©, 상표, 라이선스 이름, 주소는 글자 그대로 둔다.
  Riot Games 'Legal Jibber Jabber' 정책 문장(영어)은 정책이 정한 문장이라 그대로 — 괄호 안 우리말 풀이만 다듬는다.
  비공식 안내는 뜻(비상업 팬 메이드 · 제휴 없음 · 권리 귀속 · 요청 시 조치)을 그대로 둔다.
- **`{이름}` 꼴 자리표시.** 화면에서 값이 들어가는 자리다. 빠지거나 이름이 바뀌면 `apply`가 거부한다.
- **고정 표기.** `CASE 01~04`·`EPILOGUE` 표지와 `SKIP`(사용자 지시·명세서), 명세서의 개념어(사건 파일, 증거, 진술, 수집, 미확인 증거, 탐정님, 클루 등),
  게임과 문서의 고유 용어(Cost, 아르카나, 여정, 세트 편성 효과, 증강체, 스테이지, 구역, 우두머리, 도감, Prestige 등).
- **버튼 끝 기호.** `→`(이동) `↗`(새 탭) `⬇`(내려받기) `▶`(실행) `↺`(다시)는 누르면 무슨 일이 생기는지 알려 준다. 기호의 뜻은 유지한다.
- **같은 문구를 쓰는 키.** context에 '같은 문구: …'가 있으면 그 키들에 같은 답을 준다.
- **요약 메모의 형광펜.** `E*.memo.rows.N.hl`은 같은 행 본문(`E*.memo.rows.N.v`) 안의 글자 그대로여야 칠해진다.
  본문을 고치면 hl도 본문 속 글자로 맞춘다. 어긋나면 `apply`가 아무것도 넣지 않고 거부한다.
- **수첩 문구의 표시.** `**…**`는 형광펜, `|`는 줄바꿈(표지 도장), `[[E1:문구]]`는 증거 링크다. 표시는 그대로 둔다.
- **자기소개서 장 제목 라벨(`essay.*.label`).** 큰 제목·목차·이전/다음 버튼에 쓰이는 짧은 라벨이다. `—`를 넣지 않는다(부제와 가르는 표시).
  부제와 본문은 사용자 원고라 대상이 아니다.
- **길이.** context의 '길이' 안내를 지킨다. 버튼·라벨·장 이름·숫자 칸은 지금 길이 안팎이어야 화면에서 넘치지 않는다.
  E8 장 이름(발견 · 핵심 …)은 지도 · 옆 목차 · 장 머리에 같이 쓰이는 한 단어다.
- 키, 코드, CSS, 데이터 구조. **문구만** 바꾼다.

## 5. 하지 말 것

- 데이터 파일(`*.json`, `콘텐츠_자기소개서.md`, `index.html`)을 직접 고치지 않는다. 반드시 `apply`로 넣는다.
  `apply`는 바뀐 값만 다시 쓰고 목록을 FINAL로 맞춘다 — 손으로 고치면 `check`가 어긋남을 잡아 테스트가 실패한다.
- `Text/strings.csv`를 손으로 고치지 않는다.
- 커밋·푸시하지 않는다. `main`에 올리면 곧바로 배포된다. 커밋은 사용자가 확인한 뒤에 한다.

## 6. 키 읽는 법

| 키 | 파일 · 위치 |
|---|---|
| `E5.brief.labels.caption` | `콘텐츠_증거카드.json` → `evidences` 중 `id`가 `E5`인 것 → `brief.labels.caption` |

| `ui.evidence.title` | `콘텐츠_화면문구.json`(버튼·안내 같은 화면 공통 문구) |
| `intro.lines.3.text` | `스크립트_인트로.json` (`ending.*`는 `스크립트_엔딩.json`) |
| `notebook.part2.items.0.memo` | `콘텐츠_수사수첩.json` |
| `resume.skills.0.level` | `data/resume.json` |
| `html.title` | `index.html`(링크 미리보기·머리글) |
| `essay.CASE01.label` | `콘텐츠_자기소개서.md`의 `## [CASE01] 라벨 — 부제` 줄의 라벨 |

배열은 원소에 `id`가 있으면 `id`로, 없으면 0부터 세는 번호로 가리킨다. 규칙의 원본은 `tools/strings-lib.cjs`다.
